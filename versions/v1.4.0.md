## 🎯 Objectif de la version

La phase **v1.3.0** a livré la bibliothèque complète de widgets WooCommerce (12 types : `html`, `banner`, `custom_link`, `product_grid`, `category_grid`, `mini_cart`, `search`, `recent_posts`, `social_icons`, `newsletter`, `filters`, `title`) ainsi que le rendu frontend de ces widgets dans les menus.

La **v1.4.0** introduit la dernière brique majeure du plugin : le **Builder visuel de Headers et Footers globaux**. Le spec original (§1, §2.2, §3.6, §3.7) prévoyait un outil unifié capable de gérer en quelques clics les menus, les headers et les footers d'un site WooCommerce. Cette version finalise cette promesse.

| Fonctionnalité | Statut | Spec | Description |
|----------------|--------|------|-------------|
| Builder Header | Nouveau | §3.6, §4.6.5 | Mode « Header » dans le Builder React (rows → columns → modules). |
| Builder Footer | Nouveau | §3.7, §4.6.5 | Mode « Footer » identique au Header mais rendu en `<footer>`. |
| Header_Footer_Renderer | Nouveau | §3.6, §3.7, §5.7, §5.8 | Walker PHP pur pour layouts header/footer (9 module types). |
| Header_Footer_Injector | Nouveau | §2.8.1, §5.7, §5.8 | Hooks `wp_body_open` + `wp_footer` pour injection globale. |
| 9 module types | Nouveau | §3.6.2, §3.7.1 | logo, menu, search, cart, button, html, social, newsletter, text. |
| Settings header_footer | Nouveau | §9.5.2 | Toggle global, sélection du menu header/footer, masquage theme. |
| Switcher de mode Builder | Nouveau | §1.4.1 | Tabs Menu / Header / Footer dans l'admin. |
| Layout store Redux | Nouveau | §9.5.2 | Store `wtm/layout` dédié aux layouts (rows/cols/modules). |
| ModulePalette + Canvas | Nouveau | §3.6, §6.3 | Palette draggable + canevas visuel avec resize des colonnes. |
| ModuleProperties | Nouveau | §3.6.3 | Inspecteur de propriétés par module type. |
| Live preview iframe | Upgrade | §4.6.4 | Aperçu header/footer dans l'iframe du Builder. |
| Assets_Loader | Upgrade | §2.6 | Détection `header_footer` activé pour forcer l'enqueue. |

## ✨ Nouveautés

### 1. Backend PHP — Header_Footer_Renderer + Header_Footer_Injector

Deux nouvelles classes PHP (~1120 lignes au total) implémentent le pipeline de rendu header/footer.

**`src/Frontend/Header_Footer_Renderer.php`** (838 lignes) :
- Walker PHP pur qui parcourt les configs `_wtm_header_config` et `_wtm_footer_config` (rows → columns → modules).
- 9 renderers de modules : `logo`, `menu` (réutilise `Menu_Renderer`), `search` (réutilise le widget v1.3 avec `data-wtm-live-search`), `cart` (réutilise le mini-cart drawer v1.3), `button`, `html`, `social` (réutilise le widget v1.3), `newsletter` (réutilise le widget v1.3), `text` (avec shortcode `[year]` → année courante).
- Sortie HTML sémantique et accessible : `<header>` / `<footer>` avec `aria-label`, `data-wtm-*` pour le JS.
- Échappement systématique (`esc_attr`, `esc_html`, `esc_url`).
- Support des settings par row : `background`, `height`, `padding_y`, `align`, `hide_desktop`, `hide_mobile`, `sticky`.
- Support des settings par colonne : `width` (1-12 sur grille 12), `align`, `valign`.

**`src/Frontend/Header_Footer_Injector.php`** (288 lignes) :
- Hook `wp_body_open` (priority 10) pour injecter le header — compatible WP 5.2+.
- Hook `wp_footer` (priority 20) pour injecter le footer.
- Hook `wp_enqueue_scripts` (priority 99) pour injecter du CSS de masquage du theme natif si `hide_theme_header` / `hide_theme_footer` est activé.
- Filtres développeur :
  - `wtm_header_inject_hook` — override du hook d'injection header (ex: `storefront_header` pour Storefront).
  - `wtm_footer_inject_hook` — override du hook d'injection footer.
- Actions déclaratives :
  - `wtm_before_header` — déclenchée avant le rendu header (pour Assets_Loader).
  - `wtm_before_footer` — déclenchée avant le rendu footer.

**`src/Bootstrap.php`** :
- Instancie `hf_renderer` et `hf_injector` sur chaque requête (pas seulement is_admin).
- Le renderer reçoit `Menu_Renderer` en dépendance injectée (pour le module `menu`).

**`src/Frontend/Assets_Loader.php`** :
- Nouvelle méthode `is_header_footer_active()` qui inspecte `WTM_OPTION_SETTINGS → header_footer`.
- Si activé, force l'enqueue des assets frontend même si aucun menu n'a encore été rendu (car `wp_body_open` / `wp_footer` se déclenchent après `wp_enqueue_scripts`).
- Cache du résultat par requête (`$hf_enabled`).

### 2. Builder React — 3-col Layout mode-aware

Le Builder existant (3-col TreePanel + PreviewPanel + PropertiesPanel) est maintenant **mode-aware** grâce à un switcher de tabs Menu / Header / Footer dans le header.

**`builder/components/App.js`** :
- Sélection du mode via `useSelect(UI_STORE_NAME).getActiveMode()`.
- En mode `menu` : layout classique TreePanel + PreviewPanel + PropertiesPanel.
- En mode `header` ou `footer` : layout alternatif ModulePalette + LayoutCanvas + ModuleProperties via le nouveau composant `LayoutBuilder`.
- Propagation du dirty state du `wtm/layout` store vers le `wtm` store (menu) pour activer le bouton Save.

**`builder/components/Header.js`** :
- 3 tabs : Menu (icône `menu`), Header (icône `layout`), Footer (icône `footer`).
- L'onglet actif est mis en surbrillance.
- Le dirty dot s'affiche dès qu'un layout est modifié.

**`builder/components/LayoutBuilder.js`** (75 lignes) :
- Orchestrateur du mode layout — charge le layout depuis le menu via `loadFromMenu(activeMode, menu)`.
- Effectue `clearSelection()` au changement de mode pour éviter la sélection d'un élément qui n'existe plus dans l'autre mode.

### 3. Builder React — LayoutCanvas

**`builder/components/LayoutCanvas.js`** (276 lignes) :
- Canevas visuel en grille CSS : affiche les rows, columns et modules sous forme de cartes.
- Add / remove / select rows.
- Add / remove / resize columns (largeur 1-12 sur grille 12 via spinbutton).
- Drop de modules depuis la palette (HTML5 DnD, lit `wtm/module-type`).
- Déplacement de modules entre colonnes (HTML5 DnD, lit `wtm/module-id`).
- Click pour sélectionner (row | column | module) — l'inspecteur ModuleProperties réagit.
- Toolbar par colonne : ajout de colonne, suppression.
- Toolbar par module : suppression, drag handle.
- Résumé compact des settings dans la carte module (ex: "Menu #42", "Rechercher un produit…", "Drawer", "3 réseau(x)").

### 4. Builder React — ModulePalette

**`builder/components/ModulePalette.js`** (77 lignes) :
- 9 tuiles de modules disponibles (logo, menu, search, cart, button, html, social, newsletter, text).
- Chaque tuile affiche : icône Dashicon, nom court, description.
- Support drag-and-drop HTML5 vers une colonne du canevas.
- Click-to-add si une colonne est sélectionnée (plus rapide que le DnD).

### 5. Builder React — ModuleProperties

**`builder/components/ModuleProperties.js`** (505 lignes) :
- Inspecteur de propriétés contextuel selon le type de module sélectionné.
- Utilise les helpers `FieldRow.js` (6 helpers : TextRow, NumberRow, CheckboxRow, SelectRow, ColorRow, TextareaRow) pour réduire la duplication.
- 9 inspecteurs dédiés :
  - `logo` : image_id (media picker WP), url, max_width, alt.
  - `menu` : menu_id (select des wtm_menu existants), location.
  - `search` : placeholder, style (inline/overlay), search_sku, live_suggestions, min_chars.
  - `cart` : show_total, behavior (drawer/dropdown), drawer_position.
  - `button` : text, url, target (_self/_blank), style (primary/secondary/ghost), icon.
  - `html` : content (textarea).
  - `social` : links (textarea format "network,url" par ligne), size.
  - `newsletter` : title, placeholder, button_text, provider (internal/mailchimp/none), list_id, layout, success_message.
  - `text` : content (textarea avec mention du shortcode `[year]`).

### 6. Builder React — Layout store

**`builder/stores/layout.js`** (640 lignes) :
- Store Redux `wtm/layout` dédié aux layouts header et footer (états séparés sous `state.header` et `state.footer`).
- Actions : `loadFromMenu`, `addRow`, `updateRow`, `removeRow`, `moveRow`, `addColumn`, `updateColumn`, `removeColumn`, `addModule`, `updateModule`, `removeModule`, `moveModule`, `selectElement`, `clearSelection`.
- Selectors : `getLayout(type)`, `getSelectedElementId`, `getSelectedElementType`, `isDirty`, `getHeaderConfig`, `getFooterConfig`.
- IDs uniques générés par `genId()` (prefix + Date.now() + counter).
- MODULE_DEFAULTS par type (logo, menu, search, cart, button, html, social, newsletter, text).
- Sérialisation `serialize(type)` pour l'envoi vers la REST API.

### 7. Intégration REST API

**`src/Api/Menu_Controller.php`** :
- Le endpoint `GET /wtm/v1/menus/{id}` retourne désormais `header_config` et `footer_config` décodés.
- Le endpoint `POST /wtm/v1/menus/{id}` accepte `header_config` et `footer_config` (validés via `Schema_Validator::validate_layout()`).
- `register_meta()` déclare `_wtm_header_config` et `_wtm_footer_config` comme meta versionnés (révisions WordPress).

### 8. Schema_Validator — validate_layout

**`src/Core/Schema_Validator.php`** :
- `validate_layout($value)` valide la structure rows → columns → modules.
- `MODULE_TYPES` : 9 types valides (logo, menu, search, cart, button, html, social, newsletter, text).
- Validation stricte : `version` entier, `rows` tableau, chaque row a `id` string + `settings` + `columns`, chaque column a `id` + `width` (1-12) + `settings` + `modules`, chaque module a `id` string + `type` dans MODULE_TYPES + `settings`.
- Messages d'erreur précis avec chemin (ex: `rows[0].columns[1].modules[2] doit avoir un champ "type" dans: logo, menu, …`).

### 9. Live Preview iframe

**`src/Frontend/Preview_Controller.php`** :
- Le preview iframe du Builder gère désormais les modes header et footer.
- Nouveau message `emptyLayout: "Layout vide — ajoutez une ligne et des modules."`.
- `renderModule(mod)` rend un aperçu compact de chaque module type (logo = lien, menu = placeholder "#id", search = input, cart = icône + count, button = lien stylé, html = innerHTML, social = initiales, newsletter = form, text = texte avec `[year]` remplacé).
- `renderColumn(col)` applique `flex: 0 0 X%` selon la width.
- `renderHeader(menu)` et `renderFooter(menu)` parcourt les rows/cols/modules.

### 10. Assets CSS frontend

**`assets/front/wtm-frontend.css`** (+361 lignes) :
- Styles pour `.wtm-header` / `.wtm-footer` (background, padding, max-width container).

### 11. Builder CSS

**`builder/style.css`** (+546 lignes) :
- Layout 3-col mode-aware : `.wtm-builder__main` (menu) vs `.wtm-layout-builder` (header/footer).
- ModulePalette : grid de tuiles draggable, hover states, descriptions.
- LayoutCanvas : rows/cols/modules avec bordures, selected state, drop zones.
- ModuleProperties : formulaire d'inspection contextuel.

### 12. Settings admin — section `header_footer`

**`src/Core/Settings_Manager.php`** (déjà en place depuis v1.0.4) :

## 🐛 Bugs corrigés pendant le développement

### Bug 1 — Header search module : `data-wtm-live-search` manquant

**Symptôme** : Le module search dans un header/footer n'activait pas la recherche live (pas de dropdown de suggestions).

**Cause** : `Header_Footer_Renderer::render_module_search()` ne propageait pas les settings `live_suggestions` et `min_chars` vers les attributs HTML `data-wtm-live-search` et `data-min-chars` sur l'input.

**Fix** : Ajout de la logique conditionnelle dans `render_module_search()` pour ajouter `wtm-search--live` class + `data-wtm-live-search data-min-chars="X"` sur l'input + `data-wtm-suggestions` sur la div suggestions.

### Bug 2 — Header newsletter module : attributs JS manquants

**Symptôme** : Le module newsletter dans un header/footer ne répondait pas au submit (pas de message de succès).

**Cause** : `Header_Footer_Renderer::render_module_newsletter()` ne générait pas les attributs attendus par `initNewsletter()` du JS frontend :
- `data-provider` et `data-list-id` manquants sur le form.
- `data-wtm-newsletter-message` manquant sur le `<p>` de message.
- `<script type="application/json" data-wtm-newsletter-config>` manquant (porte le message de succès configuré).

**Fix** : Ajout de tous les attributs et du script config pour aligner le rendu sur le widget v1.3.

### Bug 3 — Pré-existant v1.2.0/v1.3.0 (rappel)

Rappel : `Menu_Renderer::render_widget()` lisait `$item['settings']` au lieu de `$item['widget_settings']` (corrigé en v1.3.0).

## 🎨 Utilisation

### Mode Builder Header

1. WP-Admin → Woo Total Menu → cliquer sur un menu existant (ou "Nouveau menu").
2. Dans le Builder, cliquer sur l'onglet **Header**.
3. Ajouter une ligne (bouton "+ Ajouter une ligne").
4. Ajouter des colonnes (bouton "+ Colonne" dans la row).
5. Régler les largeurs (1-12 sur grille 12).
6. Glisser-déposer des modules depuis la palette de gauche.
7. Configurer chaque module dans l'inspecteur de droite.
8. Enregistrer.

### Mode Builder Footer

Identique au mode Header, mais avec l'onglet **Footer**.

### Activation globale

1. WP-Admin → Réglages → Woo Total Menu → onglet "Header & Footer".
2. Cocher "Activer le Header/Footer global".
3. Sélectionner le menu qui porte la config header (champ `header_menu_id`).
4. Sélectionner le menu qui porte la config footer (champ `footer_menu_id`).
5. (Optionnel) Cocher "Masquer le header natif du theme" / "Masquer le footer natif du theme".
6. Enregistrer.

Le header et le footer seront automatiquement injectés sur toutes les pages du site via `wp_body_open` et `wp_footer`.

### Compatibilité themes

- **Themes FSE / block themes** (Twenty Twenty-Five, Twenty Twenty-Four) : `wp_body_open` est fired → header injecté en haut. ⚠️ Le header natif du theme est rendu via `template_html` — pour le masquer, activer `hide_theme_header` (CSS `display: none` sur les sélecteurs communs).
- **Themes classiques** (Storefront, Twenty Twenty-One) : `wp_body_open` est fired → header injecté. Pour Storefront, utiliser le filtre `wtm_header_inject_hook` pour s'accrocher à `storefront_header` au lieu de `wp_body_open` (afin de remplacer le header natif plutôt que d'en ajouter un second).
- **Themes sans `wp_body_open`** : le header ne sera pas injecté. Utiliser le filtre `wtm_header_inject_hook` pour pointer vers un hook custom du theme.
