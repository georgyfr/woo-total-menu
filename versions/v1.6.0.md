## 🎯 Objectif de la version

La phase **v1.5.0** a livré la bibliothèque de 12 templates intégrés, finalisant le socle fonctionnel du plugin. Restait à polir l'écosystème pour le rendre **compatible avec tout l'environnement WordPress moderne** :

- **Rôles personnalisés** : la matrice role × caps existait depuis v1.0.0, mais il manquait la possibilité de **créer des rôles dédiés** au plugin (ex. "Menu Editor") et une API REST pour les gérer à distance.
- **Blocs Gutenberg** : aucun bloc dynamique n'était exposé dans l'éditeur de WordPress — les utilisateurs devaient passer par le shortcode `[wtm_menu]`.
- **Page builders** : Elementor, Bricks et Oxygen représentaient ~70% du marché des page builders WordPress ; le plugin n'avait aucune intégration native avec eux.
- **Multisite** : l'activation réseau ne fonctionnait pas correctement (pas d'initialisation des options/caps sur les sous-sites, pas de hook `wpmu_new_blog`).

La **v1.6.0** corrige ces 4 manques en une seule release :

| Fonctionnalité | Statut | Description |
|----------------|--------|-------------|
| `Roles_Manager` + `Roles_Controller` | Nouveau | Création/suppression de rôles custom WTM + 5 routes REST `/wtm/v1/roles`. |
| 3 blocs Gutenberg | Nouveau | `wtm/menu`, `wtm/header`, `wtm/footer` server-rendered via `register_block_type`. |
| Intégration Elementor | Nouveau | Widget custom "Woo Total Menu" (si Elementor actif). |
| Intégration Bricks | Nouveau | Élément custom `wtm-menu` (si Bricks actif). |
| Intégration Oxygen | Nouveau | 3 shortcodes `[wtm_header]`, `[wtm_footer]`, `[wtm_oxygen_menu]` + helper PHP. |
| `Multisite_Manager` | Nouveau | Activation réseau + `wpmu_new_blog` + statistiques réseau. |
| `wpmu_new_blog` hook | Nouveau | Initialise automatiquement les nouveaux blogs créés après activation réseau. |
| `wtm_activated` / `wtm_deactivated` actions | Nouveau | Hooks déclencheurs post-activation/désactivation. |
| `wtm_role_created` / `wtm_role_updated` / `wtm_role_deleted` | Nouveau | Hooks déclencheurs post-opération sur rôles. |
| `wtm_multisite_blog_setup` / `wtm_multisite_blog_cleanup` | Nouveau | Hooks déclencheurs multisite. |
| `wtm_network_activated` | Nouveau | Hook déclencheur post-activation réseau. |

## ✨ Nouveautés

### 1. Rôles personnalisés — `Roles_Manager` + `Roles_Controller`

#### `src/Core/Roles_Manager.php` (~370 lignes)

Classe statique centrale qui encapsule toute la logique de gestion des rôles WordPress et des caps WTM.

**API publique** :

| Méthode | Description |
|---------|-------------|
| `Roles_Manager::get_all_roles()` | Liste tous les rôles WP avec leurs caps WTM, le compteur d'utilisateurs et le flag `is_custom`. |
| `Roles_Manager::get_role($slug)` | Récupère un rôle individuel. |
| `Roles_Manager::create_role($slug, $name, $caps)` | Crée un rôle custom (préfixe `wtm_` automatique). Vérifie l'absence de collision, accorde `read` par défaut, déclenche l'action `wtm_role_created`. |
| `Roles_Manager::update_role_caps($slug, $caps)` | Met à jour un sous-ensemble des caps WTM d'un rôle. Les caps absentes ne sont pas touchées. |
| `Roles_Manager::delete_role($slug)` | Supprime un rôle custom (jamais les 5 rôles core). Réassigne les utilisateurs vers `subscriber`. Déclenche `wtm_role_deleted`. |
| `Roles_Manager::is_custom_role($slug)` | Vérifie si un rôle a été créé par WTM. |
| `Roles_Manager::get_custom_role_slugs()` | Liste les slugs des rôles custom WTM. |
| `Roles_Manager::get_high_level_caps()` / `get_cpt_primitive_caps()` / `get_all_caps()` | Helpers pour lister les caps gérées. |

**Protection** : les 5 rôles WordPress standards (`administrator`, `editor`, `author`, `contributor`, `subscriber`) ne peuvent jamais être supprimés via l'API. Administrator a toujours toutes les caps.

**Stockage** : la liste des slugs des rôles custom est persistée dans l'option `wtm_custom_roles` (array de strings). Cela permet d'identifier sans ambiguïté les rôles gérés par le plugin.

#### `src/Api/Roles_Controller.php` (~280 lignes)

Exposé sur `/wtm/v1/roles` avec 5 routes REST :

| Méthode | Route | Permission | Description |
|---------|-------|------------|-------------|
| `GET` | `/wtm/v1/roles` | `wtm_manage_settings` | Liste tous les rôles + leurs caps. |
| `GET` | `/wtm/v1/roles/{slug}` | `wtm_manage_settings` | Détail d'un rôle. |
| `POST` | `/wtm/v1/roles` | `wtm_manage_settings` | Crée un rôle custom. Body : `{ slug, name, caps }`. |
| `PUT` | `/wtm/v1/roles/{slug}` | `wtm_manage_settings` | Met à jour les caps. Body : `{ caps: { cap: bool, … } }`. |
| `DELETE` | `/wtm/v1/roles/{slug}/delete` | `wtm_manage_settings` | Supprime un rôle custom. |

**Exemples** :

```bash
# Lister tous les rôles
curl -u admin:app_password http://localhost:8080/wp-json/wtm/v1/roles

# Créer un rôle "Menu Editor" avec accès menus + analytics
curl -X POST -u admin:app_password \
  -H "Content-Type: application/json" \
  -d '{"slug":"menu-editor","name":"Menu Editor","caps":["wtm_manage_menus","wtm_view_analytics"]}' \
  http://localhost:8080/wp-json/wtm/v1/roles

# Retirer wtm_manage_templates au rôle "editor"
curl -X PUT -u admin:app_password \
  -H "Content-Type: application/json" \
  -d '{"caps":{"wtm_manage_templates":false}}' \
  http://localhost:8080/wp-json/wtm/v1/roles/editor

# Supprimer un rôle custom
curl -X DELETE -u admin:app_password \
  http://localhost:8080/wp-json/wtm/v1/roles/wtm_menu-editor/delete
```

### 2. Blocs Gutenberg — `Gutenberg_Blocks`

#### `src/Integration/Gutenberg_Blocks.php` (~290 lignes)

Enregistre 3 blocs dynamiques server-rendered via `register_block_type` :

| Bloc | Description | Attributs |
|------|-------------|-----------|
| `wtm/menu` | Affiche un menu WTM par ID ou par emplacement. | `menuId` (int), `location` (string) |
| `wtm/header` | Affiche un header WTM (utilise la config header du menu sélectionné). | `menuId` (int) |
| `wtm/footer` | Affiche un footer WTM (utilise la config footer du menu sélectionné). | `menuId` (int) |

**Rendu serveur** : chaque bloc a un `render_callback` PHP qui délègue à `Menu_Renderer::render_by_id()` ou `Header_Footer_Renderer::render_header_by_id()` / `render_footer_by_id()`. Le HTML est généré côté serveur à chaque requête (pas de cache côté bloc).

**Placeholder** : si le bloc n'est pas encore configuré (menuId=0) ou que le menu cible n'existe pas, un placeholder HTML est retourné (`<div class="wtm-block-placeholder">…</div>`) avec un message descriptif.

**Editor JS** (`blocks/index.js`, ~210 lignes) :

- Déclare les 3 blocs via `wp.blocks.registerBlockType` ;
- Catégorie `widgets`, icônes dashicons (`dashicons-menu`, `dashicons-align-center`, `dashicons-table-row-after`) ;
- Sidebar `SelectControl` pour choisir un menu WTM publié (liste injectée via `wp_localize_script` → `wtmBlocksData.menus`) ;
- Si aucun menu WTM n'existe, affiche un `Placeholder` invitant à en créer un ;
- `save()` retourne `null` (rendu serveur pur).

**Editor CSS** (`blocks/style.css`) : styling des placeholders et des conteneurs `.wtm-header-block` / `.wtm-footer-block`.

**Build** : `webpack.config.js` modifié pour déclarer 2 entry points :

```js
config.entry = {
    index:  './builder/index.js',  // React Builder (150 KiB)
    blocks: './blocks/index.js',   // Gutenberg editor blocks (4 KiB)
};
```

### 3. Intégration Elementor — `Elementor_Integration` + `WTM_Elementor_Widget`

#### `src/Integration/Elementor_Integration.php` (~75 lignes)

Classe controller instanciée par Bootstrap **uniquement si** `class_exists('\Elementor\Widget_Base')` (lazy-loading). Enregistre le widget via le hook `elementor/widgets/register` (API v3.5+).

#### `src/Integration/Elementor_Widget.php` (~190 lignes)

Widget Elementor qui hérite de `\Elementor\Widget_Base` :

- **Name** : `wtm-menu`
- **Title** : "Woo Total Menu"
- **Icon** : `eicon-nav-menu`
- **Category** : `general`
- **Keywords** : menu, woo, wtm, mega, navigation, header

**Contrôles** :
- `menu_id` (SELECT) — liste des menus WTM publiés (récupérés via `WP_Query`) ;
- `menu_id_notice` (RAW_HTML) — astuce rappelant l'usage du shortcode.

**Render** : délègue à `Menu_Renderer::render_by_id($menu_id, '')`. Si `menu_id=0`, affiche un placeholder. Déclenche l'action `wtm_rendered_location` après rendu.

**Séparation des fichiers** : le widget est dans un fichier séparé (`Elementor_Widget.php`) pour éviter que l'autoloader PSR-4 ne charge `\Elementor\Widget_Base` quand Elementor n'est pas actif — ce qui planterait le plugin.

### 4. Intégration Bricks — `Bricks_Integration`

#### `src/Integration/Bricks_Integration.php` (~140 lignes)

Classe controller instanciée par Bootstrap **uniquement si** `defined('BRICKS_VERSION')` ou `class_exists('\Bricks\Element')`.

**Approche** :
- Hook `bricks/builder/elements` pour enregistrer l'élément custom `wtm-menu` ;
- Hook `bricks/element/render/wtm-menu` pour le rendu (délègue à `Menu_Renderer::render_by_id()`) ;
- Contrôles : `menu_id` (SELECT) + `menu_id_notice` (info) ;
- Documentation : le shortcode `[wtm_menu id="…"]` reste utilisable partout dans Bricks.

### 5. Intégration Oxygen — `Oxygen_Integration`

#### `src/Integration/Oxygen_Integration.php` (~165 lignes)

Contrairement à Elementor et Bricks, Oxygen n'a pas d'API simple pour enregistrer des éléments custom. L'intégration fournit donc **3 shortcodes additionnels** utilisables partout (y compris dans Oxygen via le bloc "Shortcode") :

| Shortcode | Description |
|-----------|-------------|
| `[wtm_header id="42"]` | Affiche un header WTM (utilise la config header du menu 42). |
| `[wtm_footer id="42"]` | Affiche un footer WTM (utilise la config footer du menu 42). |
| `[wtm_oxygen_menu id="42"]` | Alias explicite de `[wtm_menu id="42"]` pour usage dans Oxygen. |

**Helper PHP public** : la fonction `wtm_oxygen_render_menu($menu_id)` est disponible globalement pour les templates PHP Oxygen.

**Détection** : `Oxygen_Integration::is_active()` vérifie `defined('CT_VERSION')` ou `defined('OXYGEN_VERSION')`. Cependant, comme les shortcodes sont utiles même sans Oxygen, l'intégration est toujours instanciée par Bootstrap.

### 6. Multisite — `Multisite_Manager`

#### `src/Core/Multisite_Manager.php` (~210 lignes)

Classe statique qui gère l'activation/désinstallation multisite.

**API publique** :

| Méthode | Description |
|---------|-------------|
| `Multisite_Manager::is_multisite()` | Vrai si WordPress est en multisite. |
| `Multisite_Manager::for_each_blog($callback)` | Parcourt tous les blogs actifs du réseau et exécute `$callback($blog_id)` sur chacun (avec `switch_to_blog` / `restore_current_blog`). En single-site, exécute une fois sur le blog courant. |
| `Multisite_Manager::setup_blog($blog_id)` | Initialise les options WTM (`wtm_global_settings`, `wtm_db_version`) + caps + flush rewrite rules sur un blog. Idempotent. |
| `Multisite_Manager::cleanup_blog($blog_id)` | Supprime toutes les options WTM + caps d'un blog. Utilisé à la désinstallation. |
| `Multisite_Manager::on_network_activate($network_wide)` | Appelé par `Bootstrap::on_activate(true)`. Parcourt tous les blogs et applique `setup_blog`. |
| `Multisite_Manager::on_new_blog($blog_id)` | Hook `wpmu_new_blog`. Si le plugin est activé réseau, initialise le nouveau blog. |
| `Multisite_Manager::get_network_stats()` | Récupère des statistiques réseau : `total_blogs`, `total_menus`, `active_blogs`, `per_blog` (détail par blog avec menu_count). |

**Hooks déclencheurs** :

- `wtm_multisite_blog_setup` ($blog_id) — après setup d'un blog.
- `wtm_multisite_blog_cleanup` ($blog_id) — après cleanup d'un blog.
- `wtm_network_activated` — après activation réseau complète.

**Bootstrap modifié** :

- `Bootstrap::on_activate($network_wide)` accepte le paramètre WordPress standard ;
- `Bootstrap::on_deactivate($network_wide)` flush les rewrite rules de tous les blogs en multisite ;
- Hook `wpmu_new_blog` enregistré dans `register_hooks()`.

**Compatibilité ascendante** : en single-site, `for_each_blog()` exécute simplement le callback sur le blog courant sans `switch_to_blog` (zéro overhead).

## 🚀 Installation et mise à jour

### Mise à jour depuis v1.5.0

Aucune migration de base de données nécessaire. La version v1.6.0 ajoute uniquement :

- 8 nouvelles classes PHP (autoloadées via PSR-4) ;
- 5 nouvelles routes REST (auto-enregistrées par le controller) ;
- 3 blocs Gutenberg (auto-enregistrés sur `init`) ;
- 3 intégrations page builders (lazy-loaded si le builder est actif) ;
- 3 shortcodes additionnels (toujours enregistrés) ;
- 1 nouvelle option `wtm_custom_roles` (créée à la volée quand le premier rôle custom est créé).

**Pour activer les nouvelles caps sur un site existant** : aller dans `Réglages → Permissions`, la matrice role × caps est inchangée mais le bouton "Enregistrer" ré-enregistre les caps via `Permissions::register_caps()`.

### Activation réseau (multisite)

1. Télécharger le ZIP v1.6.0 ;
2. Sur le réseau `wp-admin/network/plugins.php`, upload via "Ajouter une extension → Mettre une extension en ligne" ;
3. Cliquer sur "Activer pour le réseau" ;
4. `Multisite_Manager::on_network_activate()` initialise automatiquement tous les blogs existants ;
5. Les nouveaux blogs créés ensuite seront initialisés via le hook `wpmu_new_blog`.

### Installation fraîche

1. Télécharger le ZIP : `https://github.com/georgyfr/woo-total-menu/releases/download/v1.6.0/woo-total-menu-1.6.0.zip` ;
2. Upload via `wp-admin → Extensions → Ajouter → Mettre une extension en ligne` ;
3. Activer le plugin ;
4. Les 4 fonctionnalités (rôles, blocs, intégrations page builders, multisite) sont actives automatiquement selon le contexte.

### Utilisation

#### Créer un rôle personnalisé "Menu Editor"

```bash
curl -X POST -u admin:app_password \
  -H "Content-Type: application/json" \
  -d '{"slug":"menu-editor","name":"Menu Editor","caps":["wtm_manage_menus","wtm_view_analytics"]}' \
  http://localhost:8080/wp-json/wtm/v1/roles
```

L'utilisateur `wp_menu_editor` créé ensuite dans `wp-admin → Utilisateurs → Ajouter` pourra accéder au Builder WTM mais pas aux réglages globaux.

#### Insérer un menu dans un article Gutenberg

1. Éditer un article avec l'éditeur de blocs ;
2. Ajouter un bloc "Woo Total Menu — Menu" ;
3. Sélectionner le menu dans la sidebar ;
4. Le menu est rendu côté serveur à chaque affichage de la page.

#### Utiliser un header WTM dans Elementor

1. Éditer une page avec Elementor ;
2. Rechercher le widget "Woo Total Menu" dans le panel ;
3. Le glisser dans la zone de contenu ;
4. Sélectionner le menu contenant la config header.

#### Activer le plugin sur un multisite

1. Aller sur `wp-admin/network/plugins.php` ;
2. Cliquer sur "Activer pour le réseau" ;
3. Tous les blogs existants sont initialisés ;
4. Tout nouveau blog créé sera automatiquement configuré.
