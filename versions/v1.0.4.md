## 🎯 Objectif de la version

Cette version **finalise la phase Fondations** en renforçant le `Schema_Validator` avec une validation **stricte par type d'item** et par type de widget. L'objectif est de garantir que toute configuration JSON stockée dans la base WordPress respecte un schéma précis, ce qui :

- prévient les bugs d'affichage côté frontend (à partir de v1.2.x)
- sécurise l'API REST contre les entrées malformées
- fournit une documentation **machine-readable** via le endpoint `/wtm/v1/menus/schema` enrichi
- offre une **documentation humaine** complète dans `docs/schema.md`

## ✅ Nouveautés (Added)

### 1. Validation stricte par type d'item (6 types)

`Schema_Validator::validate_item()` dispatche maintenant vers des validators spécifiques :

#### `link` — Lien simple
- **Requis** : `id`, `type`, `label`, `url`
- **Optionnels** : `target` (`_self` / `_blank`), `icon` (string), `badge` (object), `children` (array de links)

#### `mega_container` — Conteneur de méga menu
- **Requis** : `id`, `type`, `label`, `children` (au moins 1, **tous de type `column`**)
- **Optionnels** : `trigger` (`hover` / `click`), `width` (entier 200-2000 ou `"full"`)

⚠️ **Contrainte critique** : si un enfant n'est pas de type `column`, erreur `wtm_mega_invalid_child`.

#### `column` — Colonne dans un mega_container
- **Requis** : `id`, `type`
- **Optionnels** : `width` (entier 1-12, type Bootstrap), `children` (parmi `widget`, `link`, `title`, `separator`)

#### `widget` — Widget dynamique
- **Requis** : `id`, `type`, `widget_type`, `widget_settings`
- **Optionnels** : `label`, `children`

#### `title` — Titre de section
- **Requis** : `id`, `type`, `label`

#### `separator` — Séparateur visuel
- **Requis** : `id`, `type` (aucun autre champ)

### 2. Validation par type de widget (8 types)

Chaque type de widget a ses propres règles dans `widget_settings` :

| Type | Champs requis | Champs optionnels |
|------|---------------|-------------------|
| `category_grid` | — | `columns` (1-6), `categories` (array), `show_images` (bool), `show_counts` (bool) |
| `product_grid` | — | `columns` (1-6), `product_source` (5 valeurs), `limit` (1-12), `product_ids` (array) |
| `mini_cart` | — | `show_subtotal`, `show_checkout_button`, `show_thumbnail` (bools) |
| `search` | — | `placeholder` (string), `show_category_filter` (bool), `limit` (1-20) |
| `banner` | `image_url` | `link_url`, `alt`, `target` |
| `html` | `content` | — |
| `custom_link` | `label`, `url` | `target` |
| `title` | `text` | `level` (1-6) |

### 3. Validation des modules header/footer (9 types)

Les modules acceptés dans les colonnes de header/footer :

`logo` · `menu` · `search` · `cart` · `button` · `html` · `social` · `newsletter` · `text`

Chaque module doit avoir : `id` (string), `type` (parmi les 9), `settings` (object optionnel).

### 4. Validation des badges

Les badges (utilisés dans les items de type `link`) doivent respecter :

| Champ | Type | Requis | Format |
|-------|------|--------|--------|
| `text` | string | ✅ | — |
| `color` | string | non | `#RGB` ou `#RRGGBB` (regex) |
| `background` | string | non | `#RGB` ou `#RRGGBB` (regex) |

### 5. Validation de l'arborescence des layouts

Structure hiérarchique validée :

```
layout
└── rows (array)
    └── row
        ├── id (string, requis)
        └── columns (array, requis)
            └── column
                ├── id (string, requis)
                ├── width (1-12, optionnel)
                └── modules (array, requis)
                    └── module
                        ├── id (string, requis)
                        ├── type (parmi 9, requis)
                        └── settings (object, optionnel)
```

### 6. 30+ codes d'erreur explicites

Toutes les erreurs renvoient un `WP_Error` avec un code précis et un message localisé :

**Erreurs générales** : `wtm_invalid_json`, `wtm_invalid_config_type`, `wtm_invalid_version`, `wtm_invalid_items`, `wtm_invalid_settings`

**Erreurs d'items** : `wtm_invalid_item`, `wtm_missing_item_id`, `wtm_invalid_item_type`, `wtm_invalid_visibility`, `wtm_invalid_classes`

**Erreurs link** : `wtm_link_missing_label`, `wtm_link_missing_url`, `wtm_link_invalid_target`, `wtm_link_invalid_icon`, `wtm_link_invalid_children`

**Erreurs mega_container** : `wtm_mega_missing_label`, `wtm_mega_missing_children`, `wtm_mega_empty_children`, `wtm_mega_invalid_child`, `wtm_mega_invalid_trigger`, `wtm_mega_invalid_width`

**Erreurs column** : `wtm_column_invalid_width`, `wtm_column_invalid_children`, `wtm_column_invalid_child_type`

**Erreurs widget** : `wtm_widget_missing_type`, `wtm_widget_missing_settings`, `wtm_widget_invalid_label`, `wtm_widget_invalid_columns`, `wtm_widget_invalid_source`, `wtm_widget_invalid_limit`, `wtm_widget_invalid_bool`, `wtm_widget_missing_image`, `wtm_widget_missing_content`, `wtm_widget_missing_label`, `wtm_widget_missing_url`, `wtm_widget_missing_text`, `wtm_widget_invalid_level`

**Erreurs badge** : `wtm_badge_invalid`, `wtm_badge_missing_text`, `wtm_badge_invalid_color`, `wtm_badge_invalid_background`

**Erreurs layout** : `wtm_invalid_layout_type`, `wtm_invalid_rows`, `wtm_invalid_row`, `wtm_row_missing_id`, `wtm_row_missing_columns`, `wtm_invalid_column`, `wtm_column_missing_id`, `wtm_column_missing_modules`, `wtm_invalid_module`, `wtm_module_missing_id`, `wtm_module_invalid_type`, `wtm_module_invalid_settings`

### 7. Méthode `Schema_Validator::get_full_schema()`

Retourne le schéma **JSON Schema draft-04** complet avec `definitions` pour :
- `item` — Référence circulaire (un item peut avoir des enfants)
- `badge` — Objet avec text/color/background
- `layout` — Structure rows → columns → modules
- `row`, `column`, `module` — Sous-définitions

### 8. Endpoint `GET /wtm/v1/menus/schema` enrichi

Le endpoint retourne maintenant :
- Le schéma complet avec `properties` (14 champs de l'item) + `definitions` (6 sous-définitions)
- Les **listes de valeurs autorisées** pour faciliter la consommation par le builder React :
  - `item_types` (6 valeurs)
  - `widget_types` (8 valeurs)
  - `module_types` (9 valeurs)
  - `link_targets` (2 valeurs)
  - `mega_triggers` (2 valeurs)
  - `mobile_behaviors` (3 valeurs)
  - `visibility_values` (4 valeurs)

## 🔄 Modifications (Changed)

- `Schema_Validator::validate_item()` : désormais un dispatcher qui appelle des validators spécifiques (`validate_item_link`, `validate_item_mega_container`, etc.)
- `Menu_Controller::get_schema()` : enrichi avec `definitions` et listes de valeurs autorisées
- `WTM_VERSION` bumped to `1.0.4`

## 🔁 Rétro-compatibilité

✅ **Toutes les configs valides en v1.0.3 restent valides en v1.0.4** (vérifié par test unitaire).

Les nouveaux champs ajoutés en v1.0.4 (`visibility`, `classes`, `badge`, `trigger`, `width`, `widget_settings` par type) sont **tous optionnels**, donc aucune config existante ne casse.
