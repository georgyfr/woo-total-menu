## 🎯 Objectif de la version

La phase **v1.1.x** a posé tout le Builder React (squelette, CRUD items, drag & drop, live preview, historique des révisions). Jusqu'à la v1.1.5, le plugin savait **stocker** des configurations de menus mais ne pouvait pas les **afficher** côté visiteur.

La **v1.2.0** corrige cela : elle introduit le pipeline de rendu frontend complet (spec §2.4) pour les 4 types de menus :

| Type | Spec | Description |
|------|------|-------------|
| `horizontal` | §5.3, §5.4 | Méga menu horizontal (la signature du plugin) |
| `vertical`   | §5.5       | Menu sidebar avec flyout ou accordion |
| `offcanvas`  | §5.6       | Panneau latéral mobile (hamburger + drawer + overlay) |
| `footer`     | §5.7       | Multi-colonnes de liens/widgets |

## ✨ Nouveautés

### 1. `Menu_Renderer` — le cœur du rendu

**Fichier** : `src/Frontend/Menu_Renderer.php` (~800 lignes)

Classe PHP pure qui prend un `wtm_menu` post (ou sa config décodée) et retourne du HTML sémantique `<nav><ul>`. Aucun side-effect (pas d'echo, pas d'enqueue) — toute la sérialisation se fait en interne.

- **6 types d'items** gérés : `link`, `mega_container`, `column`, `widget`, `title`, `separator` (spec §3.4).
- **7 types de widgets** : `html`, `banner`, `product_grid`, `category_grid`, `mini_cart`, `search`, `custom_link` (spec §5.9).
- **4 dispatchers** par type de menu (`render_horizontal`, `render_vertical`, `render_offcanvas`, `render_footer`) qui collent aux maquettes spec §5.3 → §5.7.
- **Échappement systématique** : `esc_url`, `esc_html`, `esc_attr` partout, `wp_kses_post` pour les widgets HTML personnalisés (spec §7.10).
- **Visibilité conditionnelle** des items via `visibility: show_on_mobile|hide_on_mobile|show|hide` (utilise `wp_is_mobile()`).
- **Badges** : texte + couleur + background (hex ou rgb), échappés via regex whitelist.
- **Icônes** : si l'icône est une URL → `<img>` ; si c'est un nom → `<span class="wtm-menu__icon--{name}">` (le CSS picking up the glyph).

### 2. `Location_Interceptor` — remplacement des locations de thème

**Fichier** : `src/Frontend/Location_Interceptor.php`

Hook `wp_nav_menu_args` (priority 20). Quand un thème appelle `wp_nav_menu(['theme_location' => 'wtm_primary'])` et qu'un menu `wtm_menu` est publié pour cette location, l'interceptor remplace le walker WordPress par le rendu `Menu_Renderer`.

- **Cache objet** 5 min sur la résolution `location → menu_id` (via `wp_cache`).
- **Hook** `wtm_map_theme_location` : permet à un thème tiers de mapper ses propres locations vers les locations WTM (`primary`, `footer`, etc.).
- **Action** `wtm_rendered_location` émise à chaque rendu — permet à `Assets_Loader` de savoir qu'il doit charger les CSS/JS.

### 3. `Dynamic_CSS` — stylesheet générée à la volée

**Fichier** : `src/Frontend/Dynamic_CSS.php`

Spec §2.4.3 : « Un fichier CSS unique est généré à la volée via `Dynamic_CSS`, compilé à partir des réglages globaux (couleurs, typo, espacements) et des paramètres de chaque menu actif. »

- **Variables CSS** (`:root { --wtm-primary: …; --wtm-bg: …; --wtm-radius: …; --wtm-breakpoint: …; }`) générées depuis `WTM_OPTION_SETTINGS`.
- **Classes sticky / align / fullwidth** appliquées en fonction des `settings` par menu.
- **Sauvegarde** dans `uploads/wtm-cache/dynamic-{hash}.css` où `hash = substr(md5($css), 0, 12)`. Le hash est utilisé comme query string `?ver=` pour cache-busting.
- **Purge automatique** sur `save_post_wtm_menu`, `wtm_settings_saved`, `wp_restore_post_revision` (hook `Bootstrap::purge_dynamic_css`).
- **Sécurité** : `.htaccess` (`Options -Indexes` + `Deny from all` sur `*.php`) + `index.php` vide dans le répertoire de cache.
- **Filter** `wtm_dynamic_css` pour extensions.

### 4. `Shortcode` — `[wtm_menu]`

**Fichier** : `src/Frontend/Shortcode.php`

Spec §2.8.2 : « Un shortcode `[wtm_menu id="123"]` permet d'insérer un menu n'importe où, y compris dans des pages Elementor. »

- `[wtm_menu id="123"]` — rendu direct par ID.
- `[wtm_menu location="primary"]` — résolution automatique : trouve le menu publié pour cette location.
- Déclenche `wtm_rendered_location` → `Assets_Loader` enqueuue les CSS/JS.

### 5. `Assets_Loader` — remplace le stub v1.0.0

**Fichier** : `src/Frontend/Assets_Loader.php`

Spec §2.6.1 : « Le plugin n'enqueue ses CSS/JS que lorsqu'un menu wtm_menu est actif sur la page. »

- **Écoute** l'action `wtm_rendered_location` (émise par le shortcode et l'interceptor).
- **Enqueue conditionnel** :
  - `wtm-dynamic` (URL du CSS dynamique avec hash cache-busting)
  - `wtm-frontend` (`assets/front/wtm-frontend.css`, ~15 Ko)
  - `wtm-frontend` (`assets/front/wtm-frontend.js`, ~5 Ko, vanilla JS, dans le footer)
- **`wp_localize_script`** : passe `breakpoint`, `mobileBehavior`, `i18n` (openMenu, closeMenu, openSub, closeSub), `ajaxUrl`, `wooCartFragments` au JS.
- **Filter** `wtm_force_enqueue_assets` pour forcer le chargement (shortcodes dans contenu AJAX).

### 6. CSS et JS frontend

**`assets/front/wtm-frontend.css`** (~15 Ko) :

- Styles de base pour les 4 types de menus.
- Méga panel (grille auto-fit, animation `wtm-fade-slide` 0.2s).
- Sub-menus flyout (position absolute, hover/focus-within).
- Badges, icônes, carets.
- Widgets : product cards, category cards, mini-cart, search, banners, custom links.
- **Responsive** : breakpoint 768px par défaut, footer accordion en mobile (titres cliquables).
- **`prefers-reduced-motion`** : transitions désactivées.
- **`screen-reader-text`** utility.

**`assets/front/wtm-frontend.js`** (~5 Ko, vanilla JS, pas de jQuery) :

- **Off-canvas** : ouverture/fermeture via `[data-wtm-offcanvas-toggle]`, clic overlay ferme, ESC ferme, focus trap (Tab/Shift+Tab cycle à l'intérieur du drawer).
- **Click-trigger mega containers** : sur mobile ou en mode `trigger=click`, un clic bascule `.is-open` sur le `.wtm-menu__item--mega`. Ferme les autres mega panels ouverts au même niveau.
- **Mobile accordion** : sur mobile, un clic sur un item parent avec `href="#"` bascule ses enfants visibles.
- **Footer accordion** : sur mobile, les `.wtm-menu__footer-title` deviennent cliquables (role="button", tabindex=0, Enter/Space toggles).
- **Outside-click + Escape** pour fermer les mega panels ouverts.
- **WC mini-cart** : écoute `wc_fragments_refreshed` et rejoue une animation `wtm-bounce` (0.4s) sur le compteur.
- **Re-init** quand WooCommerce cart fragments sont rafraîchis (le mini-cart peut être remplacé).

### 7. Widgets WooCommerce

Quatre widgets dynamiques rendus via l'API WooCommerce :

| Widget | Spec | Description |
|--------|------|-------------|
| `product_grid` | §5.9.4 | Grille de produits (image, nom, prix, bouton "Ajouter"). Ordres : date, price-asc, price-desc, popularity, rating. Cache transient 12h filtrable. |
| `category_grid` | §5.9.3 | Grille de catégories avec thumbnail. |
| `mini_cart` | §5.10 | Lien vers `/cart` avec compteur + total synchronisés via WC cart fragments. |
| `search` | §5.9.5 | Formulaire de recherche produits WC (hidden `post_type=product`). |

### 8. Hooks filters pour développeurs (spec §2.8.4)

| Hook | Type | Description |
|------|------|-------------|
| `wtm_menu_config` | filter | Filtre la config avant rendu |
| `wtm_render_item` | filter | Court-circuit le rendu d'un item individuel |
| `wtm_menu_classes` | filter | Filtre les classes CSS du `<nav>` |
| `wtm_dynamic_css` | filter | Filtre le CSS généré |
| `wtm_map_theme_location` | filter | Map des locations de thème custom |
| `wtm_product_grid_query` | filter | Filtre la WP_Query du widget product_grid |
| `wtm_widget_cache_duration` | filter | Filtre la durée du transient cache |
| `wtm_force_enqueue_assets` | filter | Force le chargement des assets |
| `wtm_rendered_location` | action | Émise à chaque rendu de menu |

## 🔒 Security

- **Échappement** : `esc_url`, `esc_html`, `esc_attr`, `wp_kses_post` partout dans le rendu.
- **Couleurs** : regex whitelist hex (`#RGB` / `#RRGGBB`) ou rgb/rgba — aucune autre valeur CSS acceptée.
- **HTML personnalisé** : `wp_kses_post` (spec §7.10).
- **Cache directory** : `.htaccess` (`Options -Indexes` + `Deny from all` sur `*.php`) + `index.php` vide.
- **Widgets WC** : utilisent uniquement les fonctions API WooCommerce standard — pas de SQL brut.
