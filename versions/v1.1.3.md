# Version 1.1.3 — Fixes UX, migration React 18, ARIA propre

- **Date de sortie** : 2026-06-25
- **Statut** : ✅ Livrée
- **Tag Git** : [`v1.1.3`](https://github.com/georgyfr/woo-total-menu/releases/tag/v1.1.3)
- **ZIP de release** : [woo-total-menu-1.1.3.zip](https://github.com/georgyfr/woo-total-menu/releases/download/v1.1.3/woo-total-menu-1.1.3.zip)

## 🎯 Objectif de la version

Cette version est une **release de polish** qui corrige les 3 bugs résiduels
non-bloquants identifiés lors des tests approfondis en navigateur de la v1.1.2.

Concrètement, en v1.1.3 :

- ✅ **Indicateur de drop temps réel** — l'indicateur visuel (before/after/inside)
  se met à jour en continu pendant que le curseur se déplace à l'intérieur d'un
  même item (avant : figé au `pointerdown`)
- ✅ **Migration React 18** — `ReactDOM.render` remplacé par `createRoot` (silence
  du warning React et activation des fonctionnalités concurrentes)
- ✅ **Annonce ARIA unique en français** — la `LiveRegion` par défaut de `@dnd-kit`
  en anglais est neutralisée, seule notre annonce française est émise

Aucune nouvelle fonctionnalité : cette version ne fait que corriger des défauts
de qualité identifiés en QA.

## 🐛 Fixes (Fixed)

### 1. Indicateur de drop temps réel (spec §6.3.2)

**Problème** : pendant un drag, quand le curseur se déplaçait verticalement à
l'intérieur d'un même item (par exemple de la zone "before" vers la zone
"inside"), l'indicateur visuel ne se mettait pas à jour. Il fallait sortir de
l'item et y revenir pour rafraîchir l'indicateur.

**Cause racine** : le `useEffect` de `SortableTreeItem.js` qui recalcule la
position de drop utilisait `sortable.activatorEvent.clientY` — c'est-à-dire le Y
du `pointerdown` initial, qui ne change jamais pendant le drag. Le `useEffect`
n'était re-déclenché que par un changement de `isOver` (item survolé), pas par
le déplacement du curseur.

**Correctif** (`builder/components/SortableTreeItem.js`) :
- Ajout d'un `cursorPosRef = useRef({ x: 0, y: 0 })` pour stocker la position
  live du curseur.
- Ajout d'un state `cursorTick` (compteur entier) qui s'incrémente à chaque
  `pointermove` pendant le drag.
- Ajout d'un `useEffect` qui enregistre un listener `pointermove` global
  (uniquement quand `isDragging || isOver`), met à jour `cursorPosRef.current`
  et incrémente `cursorTick`.
- Le `useEffect` de calcul de drop position dépend maintenant de `cursorTick`
  (au lieu de `sortable.activatorEvent`), donc il se re-déclenche à chaque
  mouvement du curseur. La position est calculée depuis `cursorPosRef.current.y`.

**Correctif** (`builder/components/TreePanel.js`) :
- Ajout d'un `liveCursorYRef = useRef(0)` mis à jour par un listener
  `pointermove` global (enregistré une seule fois au montage).
- `handleDragEnd` utilise `liveCursorYRef.current` pour le calcul final de la
  position de drop (au lieu de `active.rect.current.translated?.top`).

### 2. Migration React 18 — createRoot (spec §9.2)

**Problème** : au chargement du Builder, React émettait le warning :

```
Warning: ReactDOM.render is no longer supported in React 18.
Use createRoot instead. Until you switch to the new API, your app
will behave as if it's running React 17.
```

L'app fonctionnait correctement mais tournait en mode "compatibilité React 17",
sans bénéficier des fonctionnalités concurrentes (transitions, batching
automatique, etc.).

**Correctif** (`builder/index.js`) :
- Avant :
  ```js
  import { render } from '@wordpress/element';
  render(<App initialState={initialState} />, container);
  ```
- Après :
  ```js
  import { createRoot } from '@wordpress/element';
  const root = createRoot(container);
  root.render(<App initialState={initialState} />);
  ```

`@wordpress/element` ré-exporte `createRoot` depuis `react-dom/client` (depuis
WordPress 6.2+), donc aucun changement de dépendance n'est nécessaire.

### 3. Annonce ARIA unique en français (spec §6.7)

**Problème** : après chaque drop, les utilisateurs de lecteur d'écran
entendaient **deux annonces** :
1. L'annonce anglaise par défaut de `@dnd-kit` : « Draggable item item-3 was
   dropped over droppable area item-3-1-1 »
2. Notre annonce française : « « Boutique » déplacé en position 1 dans racine. »

Cela venait du fait que `@dnd-kit/core` enregistre sa propre `LiveRegion` avec
des annonces par défaut en anglais. Notre `aria-live="polite"` custom est une
région séparée.

**Correctif** (`builder/components/TreePanel.js`) :
- Ajout d'un objet `accessibility` contenant un sous-objet `announcements` avec
  toutes les callbacks (`onDragStart`, `onDragMove`, `onDragOver`, `onDragEnd`,
  `onDragCancel`) retournant une chaîne vide `''`.
- Passage de cet objet au prop `accessibility={accessibility}` du `<DndContext>`.
- Résultat : `@dnd-kit` n'émet plus aucune annonce, seule notre région
  `.wtm-tree__sr-announcement` est lue par les lecteurs d'écran.

**Note technique** : en `@dnd-kit/core` v6, le prop `announcements` ne peut PAS
être passé au premier niveau du `<DndContext>`. Il doit être encapsulé dans le
prop `accessibility` (`accessibility={{ announcements: {...} }}`). Si on le
passe au premier niveau, il atterrit dans `...props` et est silencieusement
ignoré — la `LiveRegion` anglaise par défaut reste alors active. C'est le bug
qui a été initialement introduit dans la première itération de v1.1.3, corrigé
après tests browser.

## 📦 Détail technique des changements

### `builder/index.js` (1 changement)

```diff
-import { render } from '@wordpress/element';
+import { createRoot } from '@wordpress/element';
 // ...
-render(<App initialState={initialState} />, container);
+const root = createRoot(container);
+root.render(<App initialState={initialState} />);
```

### `builder/components/SortableTreeItem.js` (3 changements)

1. Ajout des refs/state :
   ```js
   const [cursorTick, setCursorTick] = useState(0);
   const cursorPosRef = useRef({ x: 0, y: 0 });
   ```

2. Ajout du listener pointermove :
   ```js
   useEffect(() => {
     if (!isDragging && !isOver) return;
     const onMove = (e) => {
       cursorPosRef.current = { x: e.clientX, y: e.clientY };
       setCursorTick((t) => t + 1);
     };
     window.addEventListener('pointermove', onMove);
     return () => window.removeEventListener('pointermove', onMove);
   }, [isDragging, isOver]);
   ```

3. Utilisation de `cursorPosRef.current.y` au lieu de
   `sortable.activatorEvent?.clientY` dans le calcul de drop position.
   Dépendance du `useEffect` changée de `sortable.activatorEvent` à `cursorTick`.

### `builder/components/TreePanel.js` (3 changements)

1. Ajout du `liveCursorYRef` et de son listener global :
   ```js
   const liveCursorYRef = useRef(0);
   useEffect(() => {
     const onMove = (e) => { liveCursorYRef.current = e.clientY; };
     window.addEventListener('pointermove', onMove);
     return () => window.removeEventListener('pointermove', onMove);
   }, []);
   ```

2. `handleDragEnd` utilise `liveCursorYRef.current` pour le calcul de la
   position finale :
   ```js
   const cursorY = liveCursorYRef.current
     || active.rect.current.translated?.top
     || (targetRect.top + targetRect.height / 2);
   ```

3. Ajout du prop `accessibility` au `DndContext` (encapsulant `announcements`) :
   ```js
   const accessibility = {
     announcements: {
       onDragStart: () => '',
       onDragMove: () => '',
       onDragOver: () => '',
       onDragEnd: () => '',
       onDragCancel: () => '',
     },
   };
   // ...
   <DndContext accessibility={accessibility} ... >
   ```
