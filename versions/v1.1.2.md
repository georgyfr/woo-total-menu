- **Date de sortie** : 2026-06-25

## 🎯 Objectif de la version

Cette version rend le builder **pleinement interactif** en ajoutant le **glisser-déposer arborescent** complet sur la liste des items, ainsi que l'**Undo/Redo** et les **raccourcis clavier** pour une accessibilité WCAG AA.

Concrètement, en v1.1.2 :

- ✅ **Drag & drop** via `@dnd-kit/core` + `@dnd-kit/sortable` (réordonnancement + nesting + cross-level moves)
- ✅ **Indicateurs visuels de drop** : ligne bleue avant/après, bordure pointillée pour "inside"
- ✅ **Drag handle** sur chaque item + ghost overlay qui suit le curseur
- ✅ **Auto-expand** des containers repliés après 500ms de survol
- ✅ **Raccourcis clavier** : Ctrl+↑/↓ (réordonner), Ctrl+→ (indenter), Ctrl+← (outdenter)
- ✅ **Undo/Redo** avec stacks `past`/`future` (max 50 snapshots) + raccourcis Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y
- ✅ **Annonces ARIA `aria-live="polite"`** après chaque déplacement pour les lecteurs d'écran
- ✅ **Validation des règles de nesting** en temps réel (spec §3.4.2)
- ✅ **Bug critique corrigé** : `mapItems()` ne crash plus sur les items avec enfants

## ✅ Nouveautés (Added)

### 1. Drag & Drop arborescent via `@dnd-kit`

**Stack technique** :
- `@dnd-kit/core@^6.3.1` — moteur DnD (sensors, DndContext, DragOverlay)
- `@dnd-kit/sortable@^10.0.0` — hook `useSortable` pour les items triables
- `@dnd-kit/utilities@^3.2.2` — utilitaires CSS.Transform
- `@dnd-kit/modifiers@^9.0.0` — modificateurs (non utilisés dans v1.1.2, prévus pour Header/Footer canvas en v1.2+)

**3 actions de drag supportées** (spec §6.3) :
1. **Réordonnancement** au même niveau (déplacer `item-2` avant `item-1` à la racine)
2. **Déplacement cross-level** (déplacer un `link` racine dans un `column`)
3. **Nesting dans un container** (déplacer un `column` dans un `mega_container`)

**Capteurs** :
- `PointerSensor` (souris + touch) avec contrainte `distance: 5` (évite les clicks accidentels)
- `KeyboardSensor` avec `sortableKeyboardCoordinates` pour le drag au clavier

### 2. Indicateurs visuels de drop (spec §6.3.2)

| Position | Visuel | Condition |
|----------|--------|-----------|
| `before` | Ligne bleue 2px au-dessus de l'item | Curseur dans le 1er tiers supérieur |
| `after` | Ligne bleue 2px en-dessous | Curseur dans le 3e tiers inférieur |
| `inside` | Bordure pointillée 2px + fond `rgba(108,92,231,0.05)` | Curseur dans la zone médiane (30%-70%) ET l'item est un container autorisé |

**Calcul** : `computeDropPosition(cursorY, rect, canContainChildren)` — divise la hauteur de l'item en 3 zones. Si l'item ne peut pas contenir d'enfants, `inside` est désactivé et le calcul se fait à 50%.

**Indicateur désactivé** pour les drops invalides (pas de ligne fantôme) :
- Item droppé sur lui-même
- Item droppé dans un de ses descendants
- Type d'item non autorisé dans le parent cible (ex: `link` dans un `mega_container`)
- Profondeur maximale dépassée (max 3)

### 3. Drag handle et ghost overlay (spec §6.3.1)

**Drag handle** :
- Icône `dashicons-screenoptions` (⠿ six-dot) à gauche de chaque item
- Curseur `grab` au survol, `grabbing` pendant le drag
- Couleur grise par défaut (`#9ca3af`), devient violette au survol (`#6C5CE7`)
- Séparé du bouton principal pour éviter les conflits avec le click de sélection

**Ghost overlay** (DragOverlay) :
- Carte flottante qui suit le curseur pendant le drag
- Affiche l'icône + le label de l'item déplacé
- Bordure violette `#6C5CE7`, ombre portée `0 8px 24px rgba(108,92,231,0.25)`
- Animation de drop : `cubic-bezier(0.18, 0.67, 0.6, 1.22)` 200ms

**Pendant le drag** :
- L'item original reste en place mais devient 50% transparent
- Fond `#fafafa` pour le distinguer
- Aucune mutation du state tant que le drag n'est pas terminé (spec §6.5.2)

### 4. Auto-expand des containers repliés (spec §6.3.2)

Quand l'utilisateur survole un `mega_container` ou `column` replié pendant un drag :
- Un timer de 500ms démarre
- Si l'utilisateur reste au-dessus, le container se déplie automatiquement
- Le timer est annulé si l'utilisateur déplace le curseur avant 500ms

Cela permet de naviguer dans des arbres profonds sans avoir à déplier manuellement chaque container avant de dropper.

### 5. Raccourcis clavier pour réorganiser (spec §6.3.5)

| Raccourci | Action |
|-----------|--------|
| `Ctrl+↑` | Déplacer l'item vers le haut parmi ses frères (index - 1) |
| `Ctrl+↓` | Déplacer l'item vers le bas parmi ses frères (index + 1) |
| `Ctrl+→` | Indenter : l'item devient enfant du frère précédent (si celui-ci est un container autorisé) |
| `Ctrl+←` | Outdenter : l'item rejoint la liste des frères de son parent, juste après celui-ci |

**Conditions** :
- L'item doit être sélectionné (focus clavier)
- Les raccourcis sont désactivés pendant l'édition inline (input/textarea)
- Si l'action est impossible (index 0 pour `Ctrl+↑`, racine pour `Ctrl+←`), rien ne se passe

### 6. Undo/Redo (spec §9.9)

**Stacks dans le store `wtm/menu`** :
- `past: []` — snapshots précédents (le plus récent à la fin)
- `future: []` — snapshots annulés (le plus récent au début)
- Maximum **50 snapshots** dans `past` (FIFO au-delà)

**Actions** :
- `undo()` — déplace le snapshot courant vers `future` et restaure le dernier de `past`
- `redo()` — déplace le premier snapshot de `future` vers `past` et le restaure
- `clearHistory()` — vide les deux stacks (appelé après chaque `saveMenu` réussi)

**Sélecteurs** :
- `canUndo(state)` — `state.past.length > 0`
- `canRedo(state)` — `state.future.length > 0`
- `getHistorySize(state)` — `{ past, future }`

**Comportement** :
- Chaque action mutating (`ADD_ITEM`, `UPDATE_ITEM`, `REMOVE_ITEM`, `MOVE_ITEM`, `UPDATE_MENU_TITLE`, `UPDATE_MENU_CONFIG`) pousse un snapshot de la config courante dans `past` **avant** d'appliquer la mutation, et vide `future`
- `undo` ne sauvegarde pas dans la base — il restaure juste le state local. L'utilisateur doit cliquer "Enregistrer" pour persister.
- Les révisions WordPress (spec §7.6) sont créées uniquement au `saveMenu` → sécurité long terme

### 7. Boutons Undo/Redo dans le Header

**Emplacement** : entre le titre du menu et le device switcher, séparés par une bordure verticale.

| Bouton | Icône | Raccourci | Désactivé si |
|--------|-------|-----------|--------------|
| Annuler | `dashicons-undo` | `Ctrl+Z` | `!canUndo` (past vide) |
| Rétablir | `dashicons-redo` | `Ctrl+Shift+Z` ou `Ctrl+Y` | `!canRedo` (future vide) |

**Hook global** `useEffect` sur `window.keydown` :
- Ignoré si l'utilisateur tape dans un `<input>`, `<textarea>` ou `contenteditable`
- `e.preventDefault()` pour éviter les conflits avec le navigateur
- Annonce ARIA : « Action annulée. » / « Action rétablie. »

### 8. Annonces ARIA `aria-live="polite"` (spec §6.7)

Zone invisible (`sr-only`) en bas du TreePanel avec `aria-live="polite"` et `aria-atomic="true"`.

**Messages annoncés** :

| Événement | Message |
|-----------|---------|
| Drop réussi | `« <label> » déplacé en position <n> dans <parent_label>.` |
| Drop invalide | `Déplacement invalide : la cible ne peut pas contenir cet élément.` |
| Undo | `Action annulée.` |
| Redo | `Action rétablie.` |
| Ctrl+↑/↓ réussi | `« <label> » déplacé en position <n> dans <parent_label>.` |
| Ctrl+→/← réussi | `« <label> » déplacé en position <n> dans <parent_label>.` |

**Caractéristiques** :
- Le label du parent est `racine` si `parentId === null`, sinon le label du parent
- La position est 1-indexée pour les lecteurs d'écran (plus naturel que 0-indexé)
- `aria-grabbed` sur les drag handles : `true` pendant le drag, `false` sinon

### 9. Validation des règles de nesting (spec §3.4.2)

Implémentée dans `dnd-helpers.js → isValidDrop(...)` et appelée à chaque `onDragOver` :

| Parent | Enfants autorisés | Notes |
|--------|-------------------|-------|
| `null` (racine, menu horizontal) | `link`, `mega_container`, `title`, `separator` | Pas d'`accordion_parent` en horizontal |
| `null` (racine, menu vertical) | `link`, `mega_container`, `title`, `separator`, `accordion_parent` | |
| `mega_container` | `column` UNIQUEMENT | |
| `column` | `link`, `title`, `widget`, `separator`, `accordion_parent` | |
| `accordion_parent` (vertical) | `link`, `widget` | |
| `link`, `widget`, `title`, `separator` | (terminaux) | Aucun enfant |

**Profondeur maximale** : 3 (root → mega_container → column → widget/link)

**Ancestor check** : `isAncestorOf(items, draggedId, targetId)` empêche de dropper un item dans un de ses propres descendants.

### 10. Helper `dnd-helpers.js` (nouveau fichier)

4 fonctions exportées :

```js
import {
  DROP_POSITION,
  computeDropPosition,
  isValidDrop,
  computeMoveTarget,
  isAncestorOf,
} from './dnd-helpers';

// Constants: DROP_POSITION.BEFORE, DROP_POSITION.AFTER, DROP_POSITION.INSIDE

// Compute drop position based on cursor Y
const pos = computeDropPosition(cursorY, itemRect, true);

// Validate the drop
const valid = isValidDrop({
  draggedItem, targetItem,
  targetDepth, menuType,
  position: pos,
  isAncestor: isAncestorOf(items, draggedItem.id, targetItem.id),
});

// Compute the final move target (parentId + index)
const move = computeMoveTarget({
  draggedItemId: draggedItem.id,
  targetItem, targetParentId,
  targetDepth, position: pos,
  items,
});
// move = { parentId: 'mega-1', index: 2 }
```

## 🔧 Corrections (Fixed)

### 🚨 Bug critique `mapItems()`

**Fichier** : `builder/stores/menu.js`, lignes 63-65

**Code fautif** :
```js
const newItem = mapped || item;
if (newItem.children) {
  newItem = { ...newItem, children: mapItems(newItem.children, fn) }; // ← TypeError
}
```

**Erreur** : `TypeError: Assignment to constant variable.`

**Cause** : `newItem` est déclarée `const` puis réassignée.

**Conséquence** : Toute opération d'arbre non-root (`ADD_ITEM` avec `parentId !== null`, `UPDATE_ITEM`, `REMOVE_ITEM`, `MOVE_ITEM`) sur un arbre contenant des items avec `children` crashait silencieusement le builder React. Les utilisateurs voyaient le builder se figer ou les modifications ne pas s'appliquer.

**Correctif** :
```js
let newItem = mapped || item;
if (newItem.children) {
  newItem = { ...newItem, children: mapItems(newItem.children, fn) };
}
```

### `moveItem` reducer réécrit

**Avant** (v1.1.1) :
```js
case 'MOVE_ITEM': {
  const itemToMove = findItem(state.menu.config.items, action.id);
  if (!itemToMove) return state;
  let items = removeItemById(state.menu.config.items, action.id);
  if (!action.parentId) {
    items = [...items];
    items.splice(action.index, 0, itemToMove);
  } else {
    items = mapItems(items, (item) => {
      if (item.id === action.parentId) {
        const children = [...(item.children || [])];
        children.splice(action.index, 0, itemToMove);
        return { ...item, children };
      }
      return null;
    });
  }
  // ...
}
```

**Problème** : L'index d'insertion n'était pas ajusté en fonction du retrait préalable de l'item. Si l'item déplacé était AVANT la cible dans le même parent, l'index final était décalé de +1.

**Après** (v1.1.2) : Utilisation du helper `insertItemAtIndex()` qui gère correctement l'ajustement d'index. Voir `computeMoveTarget` dans `dnd-helpers.js` pour la logique complète.
