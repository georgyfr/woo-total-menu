# Version 1.1.4 — Live preview via iframe + postMessage

- **Date de sortie** : 2026-06-25
- **Statut** : ✅ Livrée
- **Tag Git** : [`v1.1.4`](https://github.com/georgyfr/woo-total-menu/releases/tag/v1.1.4)
- **ZIP de release** : [woo-total-menu-1.1.4.zip](https://github.com/georgyfr/woo-total-menu/releases/download/v1.1.4/woo-total-menu-1.1.4.zip)

## 🎯 Objectif de la version

Cette version transforme le panneau central du Builder en **véritable aperçu
live** : ce n'est plus un placeholder statique comme en v1.1.0, mais un iframe
qui restitue en direct la configuration du menu, à chaque modification.

Concrètement, en v1.1.4 :

- ✅ **Iframe + postMessage** — le panneau central charge un iframe servi par
  le nouveau endpoint REST `/wtm/v1/preview-frame`. Le builder envoie la
  configuration du menu à l'iframe via `postMessage`, sans recharger l'iframe.
- ✅ **Debounce 250 ms** (spec §6.6) — les modifications rapides (drag,
  undo/redo, ajout d'item) sont amorties pour éviter de flooder l'iframe.
- ✅ **Modes responsive** — desktop (100%), tablet (768px), mobile (375px) avec
  bordures "device" pour visualiser le rendu sur différents écrans.
- ✅ **Rendu JS** — l'iframe contient un renderer JS qui sait afficher les 6
  types d'items (link, mega_container, column, widget, title, separator) et
  les 7 types de widgets (html, banner, product_grid, category_grid, mini_cart,
  search, custom_link).

## 🚀 Nouveautés (Added)

### 1. Endpoint REST `GET /wtm/v1/preview-frame`

**Fichier** : `src/Frontend/Preview_Controller.php` (nouveau, 540 lignes)

Ce controller expose une route REST qui retourne un document HTML
auto-contenu (CSS + JS inline, ~10 Ko). Ce document :

- Charge dans un iframe côté Builder
- Écoute les `postMessage` reçus du parent (vérification
  `event.source === window.parent`)
- Sur réception d'un message `{ type: 'wtm-render', config, device }`, met à
  jour le `body.className` avec le device et re-render le menu à partir de
  `config`
- Émet un signal `wtm-preview-ready` au parent au chargement initial

**Sécurité** :
- `permission_callback` = `current_user_can('wtm_manage_menus')`
- Header `X-Frame-Options: SAMEORIGIN` (l'iframe ne peut être embarquée que
  sur le même domaine admin)
- Header `Cache-Control: no-cache, no-store, must-revalidate` (l'iframe est
  toujours fraîche)

### 2. Composant `PreviewPanel.js` réécrit

**Fichier** : `builder/components/PreviewPanel.js` (réécriture complète)

Le nouveau composant :
- Charge l'iframe avec `src={previewFrameUrl}` (URL passée par le store UI)
- Attend le signal `wtm-preview-ready` de l'iframe avant d'envoyer des
  messages (sinon le premier message serait perdu)
- Sur changement de `menu` ou `device`, envoie un `postMessage` debounce 250 ms
- Sur changement de `device` seul, envoie immédiatement (sans debounce) pour
  que le changement de résolution soit instantané
- Deep-compare JSON du snapshot `{config, device}` pour éviter les envois
  redondants

### 3. Modes responsive (desktop / tablet / mobile)

L'iframe est wrapper dans un container `.wtm-preview__frame` qui ajuste sa
largeur max selon le device :
- `desktop` : 100% (pleine largeur)
- `tablet` : 768px, bordure sombre 6px, border-radius 12px
- `mobile` : 375px, bordure sombre 8px, border-radius 24px (look smartphone)

À l'intérieur de l'iframe, le `body` reçoit la classe
`wtm-pv-device--{device}` qui ajuste le layout du menu :
- En mobile, les menus horizontaux passent en colonne, les mega-panels
  s'affichent en statique (pas de positionnement absolu)
- En tablet, les mega-panels sont limités à 500px de large

### 4. Types d'items et widgets supportés dans le rendu

L'iframe contient un renderer JS qui sait afficher :

**Types d'items** :
- `link` — lien simple avec badge optionnel
- `mega_container` — déclencheur avec dropdown contenant les columns
- `column` — conteneur vertical à l'intérieur d'un mega_container
- `widget` — rendu spécifique selon le `widget_type` :
  - `html` : HTML arbitraire (échappé via innerHTML)
  - `banner` : bannière colorée avec gradient
  - `product_grid` : grille 2×2 de cartes produit (placeholder)
  - `category_grid` : grille 2×2 de cartes catégorie (placeholder)
  - `mini_cart` : icône panier + compteur
  - `search` : champ de recherche
  - `custom_link` (alias de link)
- `title` — libellé en majuscules (sous-titre de colonne)
- `separator` — séparateur horizontal

## 📦 Détail technique des changements

### `src/Frontend/Preview_Controller.php` (nouveau fichier)

```php
class Preview_Controller {
    const REST_NAMESPACE = 'wtm/v1';
    const REST_BASE = 'preview-frame';
    const CAPABILITY = 'wtm_manage_menus';

    public function __construct() {
        add_action('rest_api_init', [$this, 'register_routes']);
    }

    public function register_routes() {
        register_rest_route(self::REST_NAMESPACE, '/' . self::REST_BASE, [
            [
                'methods' => WP_REST_Server::READABLE,
                'callback' => [$this, 'render_frame'],
                'permission_callback' => [$this, 'check_permission'],
            ],
        ]);
    }

    public function render_frame() {
        header('Content-Type: text/html; charset=' . get_bloginfo('charset'));
        header('X-Frame-Options: SAMEORIGIN');
        header('Cache-Control: no-cache, no-store, must-revalidate');
        echo $this->get_frame_html(/* ... */);
        exit;
    }
}
```

Le HTML renvoyé contient :
- Variables CSS (`--wtm-pv-primary`, `--wtm-pv-bg`, `--wtm-pv-text`)
- ~250 lignes de CSS scoped sous `#wtm-preview-root`
- ~300 lignes de JS (renderer + postMessage listener)

## 🔒 Sécurité

| Mesure | Description |
|--------|-------------|
| Permission REST | `current_user_can('wtm_manage_menus')` obligatoire |
| X-Frame-Options | `SAMEORIGIN` — iframe limitée au même domaine |
| sandbox iframe | `allow-same-origin allow-scripts` — pas de forms, pas de top-nav |
| Origin check | `event.source !== window.parent` côté iframe (n'accepte que le builder) |
| postMessage target | `window.location.origin` côté parent (pas `'*'`) |
| Pas de localStorage | L'iframe est stateless, pas de stockage local |
| Cache-Control | `no-cache, no-store, must-revalidate` — iframe toujours fraîche |
